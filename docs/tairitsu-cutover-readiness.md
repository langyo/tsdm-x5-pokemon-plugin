# tairitsu 版替代 Dioxus 版上线的可行性研判

日期：2026-11-07 ｜ 依据：本仓库双前端并行迁移全程的实测记录

## 结论先行

**具备正式替代条件，建议按「配置默认值翻转 → 保留旧版即时回滚」的路径切换。**
功能面已全量对等且逐链路实测；性能在全最坏场景下保持交互级（<1s）；
切换开关已内建（`ui` 参数），回滚成本为零。遗留项均为已知且有明确处置方案。

## 一、功能对等（全量实测，非渲染级）

### 玩家端（`game2`，入口 `&ui=v2`）

九个页面与全部操作链路均有**执行成功**证据（非仅渲染）：

| 链路 | 证据摘要 |
| --- | --- |
| 欢迎页/初始化、首页（论坛帖+在线玩家） | verify_game2 71 断言全绿 |
| 商店购买 | toast「成功购买×1 余额:116」（136−20 精确扣款），物品入背包 |
| 背包用道具 | type_id 键控（曾修 bug），真实消耗 |
| 宠物中心治疗 | 单体/全体/逃跑后治疗 |
| 我的宠物：属性/装备/技能三页 | 改名往返、装备穿上（`equipmentid1` 落库）与卸下（toast）、学习/遗忘技能 |
| 进化 | 妙娃草→妙娃花 toast「进化成功」，species 2→3 |
| 仓库 | 移包/移仓/设首位（DB 证实）、玩家侧放生、多选+批量放生 |
| 冒险+战斗核心循环 | 开战→回合→结算→返回，无 panic |
| 战斗子流 | 战报弹窗、PP 恢复（2→7 精确）、倒下替换弹窗+执行、换人确认（site 语义正确）、精灵球捕捉（第 5 球成功，野怪入队 `result=captured`） |

### 后台（`admin2`，入口 `&index=admin&ui=v2`）

八个路由全部落地，操作对账（枚举 Dioxus 全部服务端调用）闭环：

- 列表/筛选/分页：宠物 921、物品 152、地图 123、进化链 438、技能 1126（全量加载验证）、效果 10、用户
- 七个编辑器（宝可梦/物品/地图/技能/进化链/效果/用户元数据）+ 用户发放两步向导 + 配置分节表单 + 新闻公告编辑器
- 六实体行删除（确认弹窗+服务端护栏透出）+ 用户下钻实例管理（宠物/物品实例编辑、放生、删除）
- 地图野怪管理（三个直连动作：列表/搜索添加/移除）

### 刻意不移植项（均经查证留档）

- `JsonPanel`/`JsonEditorField`：Dioxus 死码，无渲染调用点
- 文件管理器：三重死码（模块未声明、导入不存在的函数、服务端无路由）
- 物品「恢复 PP」字段：服务端不读不写，Dioxus 版输入框从未生效
- 物品「强化道具」类型：服务端 translator 无分支，提交必报错
- 技能加值效果变体：`pm_skill` 无对应列，Dioxus 版同样无法保存

## 二、性能实测（headless Edge，本机容器栈）

2026-11-08 起渲染管线切换为 diff/patch 增量（`mark_dirty` → rAF →
`flush_render` → `diff` → `apply_patches`，研究文档 §10.1.5；admin 纯增量，
玩家端含结构性批次整树替换兜底）。当前数字：

| 场景 | 旧·整树重挂 | 新·diff/patch | 评价 |
| --- | --- | --- | --- |
| 玩家端冷启动（导航→app 渲染） | 1133 ms | 1078 ms | 首次含模块加载，可接受 |
| 玩家端二次进入（导航→导航栏就绪） | 560 ms | 563 ms | 良好 |
| 页面切换（首页/背包/商店） | 21–24 ms | 21–39 ms | 即时（结构批走替换兜底） |
| 战斗回合（点击技能→DOM 更新一帧） | 21–22 ms | 19–21 ms | 即时（纯属性批走增量） |
| 后台技能页「加载更多」~1000 行 | 873–934 ms | **440–459 ms** | 减半 |
| 后台技能页全量 1126 行（11 页连载） | 10.7 s | **3.76 s** | 罕见操作 |
| 后台 1126 行全表 + 编辑弹窗开 | 776 ms | **51 ms** | 15× |
| 后台 1126 行全表 + 编辑弹窗关 | 843 ms | **24 ms** | 35× |

结论：日常交互全部 <40 ms；管理端最坏场景从「近 1s」进入「数十 ms」。

## 三、载荷与兼容

| | tairitsu (wasm2) | Dioxus (wasm) |
| --- | --- | --- |
| 游戏 wasm | 2.16 MB | 2.04 MB + lucide 412 KB |
| 后台 wasm | 1.68 MB | 2.50 MB |
| JS 引导 | boot 7 KB + glue-core 4.6 KB + shim 域模块 | 85–87 KB loader |

总体相当或更轻。两者同为 WASM + ES Modules，浏览器兼容门槛一致（现代浏览器）。

## 四、切换与回滚机制（已内建）

现状（`plugin/game.inc.php`）：
- `plugin.php?id=pokemon:game` → Dioxus 版
- `plugin.php?id=pokemon:game&ui=v2` → tairitsu 版
- 后台同理（`&index=admin[&ui=v2]`）
- 两版页面顶部均有「界面版本」切换条，双向可达

**正式替代 = 翻转默认分支**（`game.inc.php` 两处 `ui` 判断反转，旧版改挂 `&ui=v1`
逃生参数）。回滚 = 改回两行，或用户侧直接用 `&ui=v1`。双前端文件并存，互不影响，
共享同一服务端 API 面（服务端零改动）。

## 五、切换前置条件清单

1. **应用迁移 002**（剑舞 power 40→0）——与 UI 版本无关但建议一并上；
   已在种子与 `migrations/seed-fixes/` 就绪
2. **两处 UX 简化确认可接受**（功能等价、非操作缺失）：
   - Boss 配置为 JSON 文本框（Dioxus 为二级弹窗：物种搜索+个体值+倍率）
   - 技能可学种族为逗号分隔 ID 列表（Dioxus 为 chip 选择器）
3. **多浏览器/移动端抽测**：当前实测覆盖 Chromium（headless Edge）；
   Firefox/Safari 未测——同为 WASM+ESM 门槛，风险低但建议上线前抽测
4. **构建产物就绪**：`plugin/wasm2/` 由 `build_tairitsu_admin.py` /
   `build_tairitsu_poc.py` 产出，vendored glue 已含上游 #124 修复

## 六、风险与长期项

| 风险 | 等级 | 处置 |
| --- | --- | --- |
| 整树重挂在超大列表上的上限 | 低 | 实测 1126 行 <1s；若未来列表量级增长可加分页/虚拟化 |
| 上游 tairitsu 锁定 git rev `8f7a36c`（vendored） | 低 | 无运行时依赖上游发版；升级=显式重跑 vendor 流程 |
| 效果编辑器 hooks/params 为 JSON 文本框 | 低 | 服务端严格校验兜底，错误原因透出到弹窗 |
| Discuz 论坛主题对 `#app` 容器的样式干扰 | 低 | 现双前端已同壳运行多月，未见冲突 |
| Dioxus 版退役后 `plugin/wasm/` 目录 | 信息 | 确认稳定一个版本周期后可删除 |

## 七、建议路径

1. **现在**：双前端继续并存；工作人员日常使用 `ui=v2`（已可执行全部操作）
2. **短期**：完成 Firefox/Safari 抽测 → 翻转默认（`ui=v2` 为默认，`&ui=v1` 逃生）
   → 观察一个版本周期
3. **之后**：确认无回滚需求后，删除 Dioxus 前端与 `plugin/wasm/`，目录归一
